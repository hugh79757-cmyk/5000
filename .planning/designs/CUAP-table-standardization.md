## 2. 컬럼 정의 위치 (Phase 2)

- **베이스 4열 (고정, 모든 블로그):** `상품명 | 가격 | 주요 특징 | 추천 대상` — `_build_system_prompt` L458 + `extra_block` 합성
- **추가 열 (BLOG_EXTRA_RULES에서 확장):** 위 표 참조. 예) interior는 4+3=7열, camping은 4+4=8열(가격 중복 제외 시 7열).
- **가격 중복:** 추가 규칙에 "가격"이 포함된 블로그(health/pet/kitchen/beauty/camping)는 베이스와 중복. 실효 추가는 3~4열.
- **config/blogs.d/cuap.yaml:** 표/컬럼 설정 없음 — 스케줄·사이트 경로만 정의. 표 규격은 전적으로 writer.py 프롬프트에 하드코딩.

## 4. 문제 정량화 (Phase 4)

### 라이브 interior 표 (https://interior.../허리-안-아픈-숙면용-독립스프링-매트리스-베스트-품목/)
- 헤더 7열: 상품명, 가격, 주요 특징, 추천 대상, 크기(cm), 소재, 색상 옵션 수
- 총 셀 35 (5행×7열), 빈값 "-" 10셀 → **빈값 비율 28.6%**
- 원인: 소재 4/5행 "-", 색상 옵션 수 4/5행 "-" (상품 데이터에 값 없음 → 프롬프트가 "-" 표기 강제)
- 모바일: 7열은 Blowfish 테마에서 가로 스크롤 필수, 가독성 저하

### 로컬 최신 샘플 빈값
- interior 7열: 10/35 = 28.6% (소재/색상 빈값)
- pet 7열: 4/35 = 11.4%
- beauty 7열: 0/35 = 0% (LLM이 값을 채움, 허구 위험)
- 나머지 4열 블로그: 0/20 = 0% (빈값 없음 — 데이터 없으면 생략 대신 축소)

**현황 문제 요약:**
1. **컬럼 과다:** 7~8열 요구 → 모바일 가로 스크롤, 정보 밀도 과다
2. **빈값 양산:** "없으면 '-' 표기" 규칙이 빈값 10~30% 유발 (특히 크기/소재/색상)
3. **블로그간 불일치:** 4열 vs 7열 혼재 → 사용자 기대 불일치, 운영 복잡
4. **허구 유입 위험:** 빈값을 채우려 LLM이 추측값 생성 가능 (beauty 0% 빈값은 오히려 의심)

## 5. 통일안 (제안)

### 원칙
1. **최대 5열** — 모바일 가독성 기준 (Blowfish `overflow-x:auto` 없이 읽기 가능)
2. **빈값 "-" 금지 → 컬럼 제거** — 데이터 없는 열은 렌더링하지 않음
3. **베이스 4열 고정** — `상품명 | 가격 | 핵심 한줄` (기존 주요 특징+추천 대상 통합)
4. **선택 열은 데이터 있을 때만 조건부 표시**

### 필수 컬럼 (4개 고정)

| 순서 | 헤더 | 데이터 소스 | 설명 |
|------|------|-------------|------|
| 1 | # | 행 번호 | 1~5 |
| 2 | 상품명 | `product_name` (앞 20자 + 말줄임) | 브랜드 약칭 |
| 3 | 가격 | `product_price` | `286,800원` 형식 |
| 4 | 핵심 한줄 | `주요 특징 + 추천 대상` 통합 | 한 문장 15~25자, 예) "30cm 무음 스프링 — 뒤척임 많은 분" |

> 기존 "주요 특징"과 "추천 대상" 2열을 1열로 통합 → 열 절약 + 중복 서술 제거.

### 선택 컬럼 (최대 1개, 조건부)

| 후보 | 표시 조건 | 예시 헤더 | 대상 블로그 |
|------|-----------|-----------|-------------|
| 크기 | 5개 중 3개 이상에 `parsed_specs` 크기/무게/용량 값 존재 | 크기 | interior/camping/kitchen |
| 소재 | 5개 중 3개 이상에 소재 값 존재 | 소재 | interior/pet/camping |
| 성분/함량 | health/beauty 전용, 3개 이상 값 존재 | 주요 성분 | health/beauty |
| 적합 대상 | pet 전용, 3개 이상 값 존재 | 적합 | pet |

**규칙:**
- 선택 열은 1개까지만 허용 (총 5열 상한)
- 3개 미만 채워지면 선택 열 생략 → 4열로 축소
- 후보 우선순위: 크기 > 소재 > 성분/적합 (블로그별 우선순위 매핑 테이블로 관리)
- 색상/옵션 수 열은 폐지 — 본문 H3에서 서술

### 렌더링 규칙
1. 표 생성은 LLM이 아닌 **코드에서 deterministic 렌더링**으로 전환 (writer.py에 `_render_comparison_table(products)` 함수 신설, LLM 프롬프트에서는 "표는 시스템이 생성하므로 본문에 표를 만들지 마라" 지시)
2. 빈값 비율 > 30%인 열은 자동 제거 (런타임 체크)
3. 가격/상품명은 절대 "-" 금지 — 데이터 없으면 행 제외
4. 표 아래 통일 문구: `> 자세한 스펙은 아래 개별 소개를 참조하세요. 가격은 변동될 수 있습니다.`

### 프롬프트 변경
- `BLOG_EXTRA_RULES`에서 "비교표에 반드시 ... 포함, 없으면 '-' 표기" 문구 전부 제거
- 대체 지시: `비교표는 코드가 생성하므로 본문에 비교표를 작성하지 마세요. 상품별 특징은 H3에서 수치 기반으로 서술하세요.`
- `_build_system_prompt`의 "상품명 / 가격 / 주요 특징 / 추천 대상 4개 열" → "비교표는 시스템 생성, 4~5열"로 수정
