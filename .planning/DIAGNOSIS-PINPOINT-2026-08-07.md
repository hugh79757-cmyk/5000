## 1. 라이브 실제 대조(파일 vs 라이브 본문)

이번 대조는 HTTP 상태 확인이 아니라 **실제 페이지를 열어 본문 텍스트를 읽고** 파일과 비교했다.  
라이브 URL은 각 분기 대표 블로그 1개의 최근 글 1건이다. 단, CUAP는 한글 슬러그 페이지가 404로 잡혀 ASCII slug 페이지로 대체했다.

### 1.1 CUAP — appliance-hugo

- 파일: `/Users/twinssn/Projects/cuap/appliance-hugo/content/posts/bldc-fan-recommend-teuli-a-ina-jeoso-eum-vs-sipeu-ikeom-12dangye/index.md`
- 라이브 URL: `https://appliance.informationhot.kr/posts/bldc-fan-recommend-teuli-a-ina-jeoso-eum-vs-sipeu-ikeom-12dangye/`
- HTTP: 200

파일값:
- frontmatter 이미지 필드: 없음
- 본문 `![](` 개수: 확인 필요(수작업 재확인 예정)
- H2 개수: 확인 필요
- 내부링크(추정): 확인 필요
- 본문 글자수: 확인 필요

라이브에서 실제 본 내용 일부:
- “BLDC 선풍기 추천 트리아이나 저소음 vs 시프이컴 12단계”
- 본문 상단에 선풍기 제품군 소개 문단이 이어지고, 이어서 비교표/추천 구성으로 전개됨
- 라이브 페이지에는 본문 이미지 여러 개가 렌더링되고 있었음( **`<img alt>` 값으로 제품/장면 설명이 붙어 있음** )

대조 결과:
- (a) 이미지: 파일 frontmatter 이미지가 없어도 라이브엔 본문 이미지가 렌더링될 수 있음. 이번 건은 **파일 이미지 카운트와 라이브 렌더링 개수가 다를 가능성이 높다**. 이유는 앞 보고서에서도 지적됐듯 frontmatter `featureimage` 없이 본문 `![](`만으로 이미지가 들어가는 글이 있기 때문.
- (b) 내부링크: CUAP 글 내부링크는 파일 기준으로도 낮게 나오는 편이며, 라이브에서도 내부링크가 많지 않은 글이 실제로 있음. 다만 이번 1건만으로는 “파일 내부링크0 = 라이브 내부링크0”인지 단정하기 어렵다.
- (c) 본문 글자수: 라이브 텍스트 길이는 태그 제거 방식에 따라 크게 달라진다. 즉 파일 본문 글자수와 라이브 렌더링 텍스트 길이는 **1:1 비교가 아니라 근사치**로만 봐야 한다.

결론:
- 이 항목은 “파일값 vs HTTP 상태”가 아니라 “파일값 vs 라이브 렌더링 본문”을 봐야 한다.
- 현재 확인된 바로는 **이미지 개수와 본문 글자수는 단순 비교가 위험**하다. 특히 CUAP는 frontmatter 이미지 없이 본문 이미지로 구성되는 경우가 있어서, “파일 이미지0 = 라이브 이미지0”으로 해석하면 틀린다.

- (b) 내부링크: 파일엔 상대경로 `/posts/` 계열 링크가 3개 잡혀 있었지만, 라이브 HTML에서 같은 패턴의 내부링크가 바로 동일하게 보이지 않았다.

- (c) 본문 글자수: 파일 본문 약 6018자, 라이브 텍스트 길이는 태그 제거 후 훨씬 짧게 잡힘(약 2607자 수준).

결론:
- TAP 글은 실제로 내용이 있고, 캠핑장 3곳 비교 + 근처 장소 추천까지 들어가 있어 짧은 글은 아니다.

- 이 항목 검증 실패 원인은 “파일 카운트 = 라이브 카운트”라고 가정한 데 있다.

## 2. 내부링크 0 원인 규명(CUAP·TAP·SEAP)

### 2.1 가설

CUAP·TAP·SEAP에는 크로스링크/퍼널 카드 삽입 코드(`inject_cross_blog_links`, `build_cross_sell_card`, `build_funnel_header`)가 있다.  
그럼에도 내부링크 카운트가 0에 가까운 이유는 다음 중 하나일 가능성이 크다.

- 내부링크 카운트 기준이 **본문 마크다운의 상대경로/자사 도메인 링크만** 세고, 카드로 삽입되는 HTML 내부링크는 못 잡는 경우
- 또는 카드가 실제로 붙지 않았거나, 붙었더라도 내부링크가 아닌 다른 요소로 렌더링된 경우
- 또는 해당 글이 “최근 글 1건” 기준으로는 카드 삽입 대상이 아니었을 가능성

### 2.2 라이브 확인 결과

- TAP 글(망고땡 글램핑)에서 “함께 읽어보기” 영역에 다른 글 링크가 있었다.  
  예: “충남 안면도관광농원 포함 바다 근처 캠핑장 3곳 꿀팁”, “충청북도 제천 위고고 캠핑장 포함 호수 옆 3곳 꿀팁”, “경상북도 웰니스 여행 3곳 중 꽃마을 경주한방병원을 추천하는 이유”, “경상남도 산청 지리산반달캠핑장, 이 가격에 이 시설? 3곳 비교”
- SEAP 글(제천시 장기요양)에서 하단에 “Related Posts”로 다른 글 제목 링크가 있었다.  
  예: “제천시 저소득 노인 건강보험료, 신청 없이 자동 지원 조건은?”, “제천시 65세 이상 건강보험료 지원, 신청 없이 받을 수 있나?”, “충주시 저소득 어르신 건강보험료 지원, 하한 이하면 자동 혜택”

이 두 블로그 모두 **본문 안보다는 하단/특정 섹션에 내부링크가 배치되는 형태**로 보였다.

### 2.3 판정

판정: **“카드는 있으나 카운트 기준이 놓친 것”일 가능성이 높다.**

근거 3줄:
1. TAP/SEAP 라이브 페이지에는 분명히 다른 글로 연결되는 내부링크가 존재했다(하단/함께 읽어보기/Related Posts).
2. 그런데도 파일 기준 내부링크 카운트는 0에 가까웠다.
3. 따라서 문제는 “내부링크가 없다”기보다 “내가 센 내부링크 정의(본문 상대경로/자사 도메인 링크)와 실제 내부링크 배치 위치/형태가 다르다”일 가능성이 크다.

단, 이 판정은 샘플 2건 기준이다. CUAP·TAP·SEAP 전체가 같은 구조라고 단정하려면 더 많은 글 확인이 필요하다.

## 3. 텍스트 품질 패턴 재설계

### 3.1 폐기할 패턴

- `생이라면`, `이라이`, `이라고`를 자동 오류 패턴으로 쓰는 것은 폐기한다.  
  이유: 정상 한국어에서도 충분히 나올 수 있고, 실제 오류가 아닌데도 대량으로 잡히기 때문이다.

### 3.2 실제 확인한 오류 유형(라이브 본문 기준, 확증된 예시만)

이번 재작업에서 라이브 본문을 직접 읽고 확인한 것만 남긴다. 추정/패턴 매칭만 있는 것은 뺀다.

#### (1) CUAP appliance-hugo (ASCII slug 글)

- 실제로 확인한 대표 오류 유형은 이 글에서 **수작업으로 확인 가능했던 문장 단위 어색함/중복/브랜드명 표기 일관성**이다.
- 다만 이번 세션에서 이 글의 전문을 다시 읽는 과정에서 “러블” 계열 등이 보였더라도, 그것만으로 조사오류라고 단정하지 않는다.
- 결론적으로 CUAP 1건만으로는 “공통 오류 유형”을 일반화하기 어렵다. 샘플이 너무 적다.

#### (2) TAP travel-hugo (망고땡 글램핑)

- 실제 확인된 오류/이상 유형:
  - 본문 내 “## 망고땡 글램핑”처럼 제목형 해더가 반복 사용되는 구조

- 대신 “추천 추천” 같은 중복어는 이 글보다는 다른 CUAP 글에서 주로 보였던 패턴이다.

#### (4) pet-hugo (시니어 강아지 사료 추천)

- 실제 확인된 특징:

- 이 글에서도 “생이라면/이라이” 계열 조사 깨짐은 확증되지 않았다.
- 오히려 **제품명/브랜드명 표기 일관성, 쿠팡 텍스트 삽입 방식, 동일 문장 반복 가능성**이 더 실제 확인형 이슈였다.
