# CONTEXT.md — Phase 67: 무인 운영 시스템 (Unattended Ops)

## 배경

- 5000 파이프라인은 50+ 블로그를 자동 발행 중이나, 여전히 사람 개입이 필요한 영역이 있음
- 현재 텔레그램 알림 26건(leak_detected 유형) 중 진짜 사람 개입이 필요한 것만 남기고 나머지는 대시보드/요약으로 흡수해야 함
- 오토트리아지는 dry-run 검증만 완료된 상태 (228건→자동97/사람26/skip105), 실모드 미등록
- dead 링크: 75개 고유 dead URL, 461건 링크, 186개 글, 10개 블로그 — 방안 A(코드) 완료, 방안 B(DB)·라이브 청소·백필 검증 미집행
- 목표: 사람 개입이 "하루 1~2회 요약 확인" 수준으로 축소된 무인 운영 시스템 완성

## 계약 (계획 시 준수할 제약)

1. **연구→게이트→집행 순서 엄수**: R1-R4 리서치 완료 → G1-G4 게이트 통과 확인 → E1-E5 집행. 게이트 미통과 시 그 지점에서 멈추고 대안 제시.
2. **이미 완료된 작업 재실행 금지**: C04 오탐 제거(0457387be), senior 중복필터+재시도(4d74d1131), STATE 관찰지표(bd0ff7be3), 오토트리아지 골격(e2137bb60), 방안 A 완료(fcbdd18e1), 파일럿 1건(캠핑-필수템) 제거·배포·라이브 확인 — 이 작업들은 재실행하지 않음.
3. **푸시는 하지 않음**: wrangler 재배포는 라이브 청소에 한해 허용. 코드 변경은 커밋하되 push는 사용자 요청 시에만.
4. **백업 태그 생성**: 집행 시작 전 `git tag pre-unattended-phase-2026-08-08` 생성.
5. **파괴적 작업 프로토콜 준수**: DB UPDATE/DELETE는 사전 카운트→백업→실행→사후 대조 4단계 필수. `.planning/worklog/WL-<날짜>-<주제>.md` 기록.
6. **라이브 확인의 최우선**: 파일 통계만으로 판정하지 않고 HTTP HEAD/GET으로 라이브 확인 (OPERATIONS-CHARTER 원칙 4).

## 확정 설계된 방향

- dead 엔티티 재발 방지 3중 완결: 코드(방안 A, 완료) + DB(방안 B) + 재등록 차단(백필 검증)
- 오토트리아지 실모드 등록: PROBLEM_ALERT_DRY_RUN=0으로 전환, launchd/cron 등록, watchdog 감시 포함
- 대시보드 서버(app.py) 의존성 해소: 서버 미기동 시에도 트리아지가 죽지 않거나 자동 기동
- 텔레그램 알림: 사람 개입이 진짜 필요한 것만 발송, 나머지는 대시보드/요약으로

## 성공 기준 (Exit Criteria — 5항목)

1. 라이브에 사용자 노출 dead 링크 0건 (잔여는 집계·근거와 함께 명시)
2. dead 엔티티 재발 방지 3중 완결: 코드(방안 A) + DB(방안 B) + 재등록 차단(백필 검증)
3. 오토트리아지가 dry-run이 아닌 실제 모드로 스케줄에 등록돼 자동 실행되고, 대시보드 서버 의존성이 해소
4. 텔레그램에는 사람 개입이 진짜 필요한 것만 오고(현재 26건 leak_detected 유형), 나머지는 대시보드/요약으로 흡수
5. 사람의 정기 개입이 "하루 1~2회 요약 확인" 수준으로 축소됐음을 수치로 입증

- 콘텐츠 품질 개선 (별도 phase)
- 광고 배치/수익 최적화 (별도 phase)
