# nomad.techpawz.com 이미지 851건 전량 소실 복구 (R2 재활성화 + 백필)

## 배경

`nomad.techpawz.com` 156개 포스트 중 **145개 페이지의 이미지 851건이 전부 404**다. HTML은 정상 렌더링되고 `<img>` 태그도 8개씩 살아있지만, `src`가 가리키는 R2 오브젝트가 없다. 글은 읽히지만 사진 자리가 비어 있다.

**근본 원인 (2중 확인됨):**

1. `pipelines/etap/image_fetcher.py:171` `_upload_to_r2()`가 working tree에서 차단 상태다. 커밋된 HEAD는 정상 업로드하지만, 미커밋 편집이 early return 3줄로 교체했다:
   - `[BLOCKED 2026-10-01] ETAP R2 업로드 중단 — 대표님 지시로 etap/ 이미지 업로드 비활성화`
2. R2 버킷 `hotissue-images`의 `etap/` 프리픽스에 오브젝트가 **0개**다 (버킷 전체 30,552 오브젝트 list로 확인). 즉 업로드를 멈춘 이후 발행된 포스트는 URL만 찍히고 파일은 없는 상태였다.

**결정: 배포·재빌드가 필요 없다.** 라이브 HTML이 이미 절대 R2 URL을 참조하므로, 없는 키를 채우는 것 자체가 온전한 수정이다. Hugo 빌드 없음, `wrangler` 없음, `/Users/twinssn/Projects/ETAP` 내부 편집 없음 (그 저장소는 이미 미커밋 184파일이라 손대지 않는다).

**잘못된 slug 1건 — 수정하지 않고 보고만 한다.** `goreme-digital-nomad-guide`의 featureimage이 `https://pub-…r2.dev/common/default-thumbnail.webp`를 가리킨다. `audit-report.json`의 `exists: true`이며 라이브 HTTP 200도 확인했다(2026-10-04). 즉 깨진 링크가 아니라 공유 기본 썸네일 fallback이다. 무의미하게 본문 slug 디렉터리로 옮기면 공유 썸네일 자산을 오염시키므로 **내용물 손대지 않고 보고한다.**

## 설계

**Task 1 — 업로드를 되살린다.** 차단 early return 3줄을 지워 HEAD 동작으로 복귀시킨다. 이게 없으면 다음 발행도 같은 방식으로 이미지를 잃는다.

**Task 2 — 되쓸 수 있는 백필 스크립트.** 일회성 스크래치패가 아니라 저장소에서 살아남는 도구로 만든다. 다른 ETAP 사이트 ~36개가 같은 `etap/` 프리픽스를 공유하므로 나중에 `--site`만 바꿔 재사용할 수 있어야 한다.

`audit-report.json`의 기계적 전수조사 결과가 이미 있으므로 **콘텐츠를 다시 스캔하지 않는다.** `detail`이 곧 작업 목록이다. 각 항목에서 필요한 정보만 뽑는다:

- `target` (`hotissue-images/etap/{slug}/{cover|body_N}.{ext}`) → R2 키. **확장자를 그대로 존중한다.** 286개 `.jpg` 키는 HEAD의 `.jpg`→`.webp` 재작성 이전에 만들어진 것이므로, 키를 정규화하지 않고 `.jpg` 오브젝트를 그 자리에 올린다. `.webp` 키는 `_to_webp()`로 인코딩. 콘텐츠 URL은 절대 고치지 않는다.
- `field` → `cover` / `body_N`
- 크레딧 → **같은 필드의 사진 출처를 되살리기 위한 검색 키워드**

**크레딧 매칭이 우선인 이유.** 본문 이미지 바로 뒤에 `*Photo by [Name](...) on [Pexels](...)` 크레딧 줄이 이미 박혀 있고, 이 조사에서 **851건 중 689건(81%)의 크레딧 줄을 복원 가능**하다(featureimage 29/132, body 660/719). 크레딧에 적힌 사진작가 이름으로 먼저 검색하면 원본 사진을 그대로 찾아 attribution이 유지된다. 그래도 못 찾으면 도시/국가 쿼리로 대체하되, 그 162건은 **크레딧 불일치 건수로 정직하게 보고한다** — 몰래 다른 사진을 넣고 "정상"이라 하지 않는다. (콘텐츠 수정이 금지되어 있어 잘못된 크레딧을 고칠 수 없다. 숨기는 게 답이 아니다.)

**검색 재사용 (새 클라이언트 금지).** `pipelines/etap/image_fetcher.py`의 `_search_with_fallback()` / `_search_pexels()` / `_search_unsplash()` / `_to_webp()`를 그대로 import한다. `requests` + Pexels + Unsplash 클라이언트를 다시 쓰지 않는다. `PEXELS_API_KEY`와 `UNSPLASH_ACCESS_KEY`는 `shared/env_loader` 경유로 SET 확인됨(각 56/43자). `_is_image_used()`는 **호출하지 않는다** — 851장을 이미 전부 썼다고 표시된 전역 중복 가드가 백필 자체를 막는다. 대신 성공한 사진 URL은 `_mark_image_used()`로 기록해 *앞으로의* 발행이 같은 사진을 재사용하지 않게 한다(`INSERT OR IGNORE`, 순수 추가).

**후보 인코딩 규칙.** 검색 API는 확장자를 보장하지 않는다(`.jpg` 키인데 webp/png 바이트가 올 수 있음). `_encode_for_ext(raw, ext)` 한 헬퍼: 확장자가 `.webp`면 `_to_webp()`, `.jpg`면 Pillow로 JPEG 재인코딩 후 `content_type="image/jpeg"`. 바이트를 그대로 올리면 MIME 불일치로 브라우저 렌더가 또 깨진다.

**파괴적 작업 아님 — 단, 코드에서 보장한다.** 이번 R2 put은 전부 신규 오브젝트다(사전조사로 `etap/` 하위 0건). 그래도 방어는 코드에 박는다: (1) `file_exists()`로 기존 키 있으면 **건너뛰고 덮어쓰지 않는다**, (2) 키 정규식 `^etap/[a-z0-9._-]+/(cover|body_\d+)\.(jpg|webp)$` 불일치하면 즉시 거부. (2번은 마크다운 콘텐츠에서 유도된 키가므로 경로 탈출(`../`)을 막는다.

**재개 가능성.** append-only JSONL 진행 로그 `data/backfill_etap_r2_images.jsonl`에 키마다 한 줄(`{"key","status","src"}`). 시작 시 읽어 `ok`/`skip`인 키를 건너뛴다. 타임아웃으로 죽어도 진행 손실 없음.

**Pexels 200 req/hr 상한 (계획에 반영 필수).** 851개 검색은 시간당 상한을 넘어선다. 그래서 `--max-per-run N`(기본 150)을 둔다. 한 번에 150개씩 처리하고 재실행해 topping up한다. 429는 `fail`(재시도 가능)로 기록하고 다음 런이 이어받는다. 5시간짜리 단일 실행을 만들지 않는다.

**동시성.** `ThreadPoolExecutor(max_workers=4)` 기본. R2/Pexels 모두 감당하며 폭주를 막는다. `--workers`로 조정.

**Task 3 — 실행 + 검증.** self-check → dry-run → 배치 실행 → 전수조사 재실행 → 라이브 페이지 확인. 보고 3분법([검증됨]/[부분검증]/[검증불가])과 잔존 위험을 반드시 남긴다.

## 제약

- **배포 없음.** `hugo`/`wrangler`/`dispatcher.py` 호출 금지. 라이브 HTML은 이미 올바른 절대 URL을 참조한다.
- **`/Users/twinssn/Projects/ETAP` 내부 파일 수정 0건.** 읽기 전용으로 크레딧 파싱에만 접근.
- **콘텐츠 URL 재작성 금지.** 확장자 정규화 금지.
- **R2 오브젝트 덮어쓰기 0건.** `file_exists` 스킵이 이를 강제한다. `common/` 등 `etap/` 밖 오브젝트는 손대지 않는다.
- **`goreme` wrong-slug 링크는 보고만.** 존재하는 공유 썸네일이다.
- 다른 ETAP 사이트 ~36개는 이번 범위 밖. 스크립트가 재사용 가능하면 충분하다.
- 조용한 실패 금지 — `fail`은 반드시 카운트와 함께 stdout에 찍는다.
- 토큰·API 키 값을 로그·SUMMARY·커밋에 쓰지 않는다(이름만).

5. **샘플 HTTP 200** — 진행 로그에서 무작위 20개 키를 뽑아 공개 URL GET:
   ```

   ks=[json.loads(l)['key'] for l in open('data/backfill_etap_r2_images.jsonl') if json.loads(l)['status']=='ok'];
   random.seed(7); s=random.sample(ks,min(20,len(ks)));
   bad=[k for k in s if urllib.request.urlopen('https://pub-2f5c7af1c303419a933069212bc25874.r2.dev/'+k,timeout=20).status!=200];
   print('sampled',len(s),'bad',bad); assert not bad"
   ```
6. **라이브 실증** (`.claude/skills/etap-live-verification` Stage 5, 배포 없는 변형) — 실측된 라이브 URL 4개가 모두 HTTP 200임을 확인했다:
   ```
   for s in bali-digital-nomad-guide abdeen-digital-nomad-guide cape-town-digital-nomad-guide amsterdam-digital-nomad-guide; do
     n=$(curl -sL "https://nomad.techpawz.com/posts/$s/" | grep -oE 'r2\.dev/etap/[a-z0-9._/-]+\.(jpg|webp)' | sort -u | while read u; do curl -s -o /dev/null -w '%{http_code} ' "https://$u"; done)
     echo "$s -> $n"
   done
   ```
   각 URL에 404가 없어야 한다. `200 200 ...` 형태로 출력되면 통과.
7. 덮어쓰기 없음 확인: `audit-report.baseline.json`의 851개 키 전부에 대해, 그 중 851개 모두 이번 실행에서 `ok`가 되었고(사전 0건이므로) `skip`은 0건이어야 한다. `skip > 0`이면 기존 오브젝트를 만났다는 뜻 — 사전조사와 어긋나므로 반드시 보고하고 재확인한다.
