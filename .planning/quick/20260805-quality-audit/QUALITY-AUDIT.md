### 1-3. 핵심 문제 상세

#### 문제 1: 제목-본문 수치/지역 불일치 (travel1-hugo, travel3-hugo)

** travel1-hugo: 제목 "5곳" vs 본문 3곳 **
- 파일: `울산공업축제와-함께하는-지역-행사-5곳-정리`
- 제목: "울산공업축제와 함께하는 지역 행사 **5곳** 정리"
- 본문 H2: 울산공업축제, 성남동 커피페스티벌, 울산대공원 장미축제, 울주 간절곶 해맞이 = **4곳** (5곳 아님)

** travel3-hugo: 제목 "계룡시" vs 본문 "서산시" **
- 파일: `현지인만-아는-충남-계룡시-맛집-3곳-총정리`
- 제목: "현지인만 아는 충남 **계룡시** 맛집 3곳"
- 본문 식당: 집으로회센타(**서산시**), 안흥일품꽃게장(**서산시**), 진국집(**서산시**)
- **3곳 전부 서산시** — 제목과 본문 지역 불일치

#### 문제 2: 쿠팡 링크 무관 매칭 (compare-hugo)

- 파일: `xm-vs-g클래스-7개-항목-완전-비교...`
- 글 주제: BMW XM vs G클래스 차량 비교
- 쿠팡 링크: "차량용 트렁크 정리함", "LG 퓨리케어 미니공기청정기"
- **차량 비교글에 트렁크 정리함/공기청정기 링크는 무관**

#### 문제 3: 범용 문장 과다 (travel1-hugo, travel3-hugo)

- travel1-hugo: "이번 글에서는", "소개합니다", "정리하였습니다" 등 범용 패턴 1-2건/글
- travel3-hugo: "이번 글에서는 계룡시와 인접한 서산 지역에서...", "각 식당의 위치, 영업 정보..."
- **고유 정보(해당 지역/축제만의 사실) 비율 낮음**

#### 문제 4: hotissue-hugo 본문 2자 포스트

- 파일: `2026-02-11-069-2026nyeon-jeongicha-chungjeonyogeum-bigyo`
- 본문: 2자 (거의 비어있음)
- **원인**: RSS/외부 발행에서 생성된 더미 포스트

#### 문제 5: travel2-hugo 쿠팡 링크 과다

- 파일: `순천-송광사-국사전의-시대적-배경과-건축적-특징-분석`

### 2-2. CAP 데이터 출처 조사 (2026-08-05)

**조사 대상**: compare-hugo/tco-hugo에 사용되는 잔존가치, 3년 총비용, 세후월급, 유지비 등 수치가 LLM 생성인지 DB/수식 기반인지

**결과: LLM 생성 아님 — 결정론적 수식 + DB 질의**

| 수치 | 출처 | 검증 |
|------|------|------|
| 신차 가격 | `trims` 테이블 (DB) | ✅ 실데이터 |
| 연비 | `public_fuel_data` 테이블 (DB) | ✅ 실데이터 (opinet) |
| 연료비 | `fuel_price_cache` × 연비 × 15,000km | ✅ 실데이터 + 수식 |
| 자동차세 | 배기량 기반 수식 (`calc_tax()`) | ✅ 국세청 공식 |
| 보험료 | 가격대별 고정 브acket (`calc_insurance()`) | ⚠️ 단순화 (70~450만원) |
| 잔존가치 | 브랜드/연료/세그먼트별 기본율 + 연차별 감가 커브 (`estimate_resale()`) | ⚠️ hardcoded, `resale_prices` 테이블 0건 |
| 3년 총비용 | 감가 + (세금+보험+유류비)×3 | ✅ 수식 |

**프롬프트 지시**: "아래 JSON 데이터에 있는 수치만 사용하세요. 데이터에 없는 숫자를 지어내지 마세요."

**남은 리스크**:
- `estimate_resale()`의 브랜드별 기본율이 실제 중고 시장과 다를 수 있음 (검증 필요)
- `calc_insurance()`의 가격대별 고정 브acket이 실제 보험료 대비 부정확할 수 있음
- `resale_prices` 테이블이 비어 있어 실제 리셀 데이터와 비교 검증 불가

### 잔존 위험

1. **CAP 잔존가치 수식 정확도 미검증**: `estimate_resale()` 브랜드별 hardcoded 기본율 — 실제 중고 시장 대비 오차 미측정. `resale_prices` 테이블 0건으로 비교 검증 불가.
2. **CAP 보험료 단순화**: `calc_insurance()` 가격대별 고정 브acket (70~450만원) — 실제 보험료 대비 과단순.
3. **Q2 오탐 다수**: travel 시리즈 "시대명" 패턴(조선시/고려시)이 "시"로 매칭되어 56건 오탐 — 정밀 필터링 필요.
4. **travel3-hugo 제목-본문 지역 불일치**: 현재 라이브에 노출 중. 게이트 구현 전까지 수동 모니터링 필요.
5. **writer 본체 리라이팅**: 구조 다양화, 수치 가드레일, 고유성 강화 — 다음 단계.
