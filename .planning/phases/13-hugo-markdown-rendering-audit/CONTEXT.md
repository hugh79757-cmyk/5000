# Phase 13 Context: Hugo Markdown Rendering Audit & Fix — Cross-Project

## Problem Statement

Multiple Hugo sites across 5000 project (and TAP project) exhibit **visible raw markdown syntax** in published articles due to Hugo's Goldmark engine not processing markdown inside raw HTML blocks.

**Observed issues:**
- `**bold**` rendered literally in `<figcaption>`, `<p>`, `<li>`, `<div>` blocks
- `~~strike~~` not converted inside HTML wrappers
- Mixed HTML + markdown content from AI output not properly sanitized
- Lead paragraph (`<p class="lead">`) — already fixed in `hugo_writer.py` but not retroactively

## Root Cause

1. **Pipeline level**: `hugo_writer.py` wraps content in HTML blocks (`<p class="lead">`, `<figure>`, `<figcaption>`, accordion/gallery shortcodes) AFTER AI generates markdown
2. **Hugo behavior**: Goldmark does NOT process markdown inside raw HTML elements
3. **Legacy content**: Existing `content/posts/**/index.md` files already contain raw `**bold**` inside HTML blocks from prior generations

## Previous Fixes (Partial)

- ⚠️ **Gap**: Not all HTML contexts covered (figcaption, raw <p>, accordion content, etc.)
