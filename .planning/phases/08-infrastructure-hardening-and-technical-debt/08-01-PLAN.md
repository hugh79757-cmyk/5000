# Plan 08-01: Infrastructure Cleanup — venv, requirements, hardcoded paths

**Phase:** 8 — Infrastructure Hardening & Technical Debt
**Goal:** venv 단일화, requirements 버전 고정, 하드코딩 경로 제거
**Mode:** refactor

## Objective

Phase 6 C에서 pip 업데이트 후 pydantic-core 2.47.0 충돌이 발생했다. 근본 원인은 requirements.txt가 전부 `>=` loose pin이고 pydantic/pydantic-core가 명시되지 않은 탓이다. 또한 STAP/.venv는 아무도 안 쓰는 빈 디렉토리이고, BLOG_SITE_PATHS는 `/Users/twinssn` 절대경로에 의존한다.

## Tasks

### 1.1 5000/requirements.txt 버전 고정

**파일:** `5000/requirements.txt`

**수정 전:**
```
openai>=1.30.0
```

**수정 후 (SAP requirements.txt 버전 기준):**
```
openai==2.21.0
pydantic==2.12.5
pydantic-core==2.41.5
httpx==0.28.1
```

**나머지 패키지도 `pip freeze` 기반으로 `==` 고정.** 단, ruff/mypy/pytest는 `>=` 유지 (dev 의존성).

**이유:** SAP이 `openai==2.21.0` + `pydantic==2.12.5` + `pydantic_core==2.41.5` 조합으로 가장 안정적으로 돌아가고 있음. 이 버전이 5000과 TAP에서도 동작 검증됨.

**위험:**
- openai 2.21.0은 2.41.0(5000 현재)보다 기능이 적을 수 있음. `chat.completions.create` 인터페이스는 동일하므로 영향 없어야 함.
- 설치 후 `pip check`로 의존성 충돌 없는지 반드시 확인.

### 1.4 BLOG_SITE_PATHS → shared/paths.py 이관

**파일:** `shared/publisher.py` (L396-403), `shared/paths.py`

BLOG_SITE_PATHS를 shared/paths.py로 이동하고 publisher.py는 import해서 사용.

**shared/paths.py에 추가:**
```python

    "dividend-hugo": os.path.join(_STAP_ROOT, "dividend-hugo"),
```
