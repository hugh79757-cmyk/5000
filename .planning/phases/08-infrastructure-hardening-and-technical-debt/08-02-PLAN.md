**Phase:** 8 — Infrastructure Hardening & Technical Debt
**Goal:** `_inject_related_cards()` 변수 초기화 버그 수정 + ai_writer resilience 강화
**Mode:** fix

## Objective

`_inject_related_cards()`에서 `cross_found` 변수가 초기화되기 전에 travel 블록에서 append를 시도한다(NameError 위험). 또한 travel 블록에서 append한 결과를 L476의 `cross_found = []`가 덮어쓴다. ai_writer는 49곳에서 import되는 SPOF인데 retry에 exponential backoff와 circuit breaker가 없다.

## Tasks

### 2.1 `_inject_related_cards()` cross_found 변수 초기화 순서 버그 수정

**파일:** `shared/publisher.py` (L327-527)

**버그 1:** L452-470 travel 블록에서 `cross_found.append()`를 호출하는데, `cross_found`는 L476에서 처음 선언됨. L452 시점에 `cross_found`는 NameError.

**버그 2:** L476 `if not cross_found: cross_found = []`가 travel 블록의 append 결과를 무조건 덮어씀.

**수정 방안:** `cross_found`를 함수 초기(cards 선언 직후, L388 근처)에 빈 리스트로 선언하고, travel 블록과 cross-blog 블록이 같은 리스트를 공유하게 만든다. 또한 cross-blog 블록의 중복 append 방지 로직(L496)이 travel 블록 결과도 포함하도록 `cards + cross_found`가 아닌 `cards + cross_found`를 그대로 유지.

**수정 코드 (L388 주변, 기존 L476 제거):**
```python
cards = []
cross_found = []  # ← 여기로 이동, L476의 if block 제거
```

**변경 후 구조:**
```
L388: cards = []
L389: cross_found = []     # ← NEW: 함수 초기에 선언
L394: # ① same-blog (cards.append)
L451: # ② travel (cross_found.append) ← NameError 해결
L472: # ③ cross-blog keyword (cross_found.append) ← 중복 덮어쓰기 해결
L504: cards.extend(cross_found)
```

**영향도:** `_inject_related_cards()`는 모든 발행 파이프라인의 포스트 프로세싱에서 호출됨. travel 블로그가 아닌 블로그는 ② travel 블록을 건너뛰므로(cross_found가 빈 리스트 그대로) 동일하게 동작.

### 2.2 ai_writer resilience 강화 — exponential backoff + circuit breaker

**파일:** `shared/ai_writer.py` (L52-121)

**현재:**
```python
MAX_RETRIES = 2
TIER_ORDER = ["default", "fallback", "economy"]
for attempt_tier in attempted_tiers:
    try:
        client.chat.completions.create(...)
    except Exception as e:
        logger.exception(...)
        continue
```

**수정:**
```python
import time
MAX_RETRIES = 3
TIER_ORDER = ["default", "fallback", "economy"]
CIRCUIT_BREAKER_THRESHOLD = 10     # 연속 실패 N회 → 차단
CIRCUIT_BREAKER_RESET_SEC = 300    # 5분 후 자동 복구

_circuit_state = {"failures": 0, "open_until": 0.0}  # 모듈 레벨

for attempt_tier in attempted_tiers:
    # circuit breaker 체크
    if _circuit_state["open_until"] > time.time():
        logger.warning("[ai_writer] Circuit breaker OPEN — 5분 대기")
        time.sleep(60)
        continue

    for attempt in range(MAX_RETRIES):
        try:
            client = get_client(...)
            response = client.chat.completions.create(**kwargs)
            # 성공 → circuit breaker 리셋
            _circuit_state["failures"] = 0
            _circuit_state["open_until"] = 0.0
            return result
        except Exception as e:
            _circuit_state["failures"] += 1
            if _circuit_state["failures"] >= CIRCUIT_BREAKER_THRESHOLD:
                _circuit_state["open_until"] = time.time() + CIRCUIT_BREAKER_RESET_SEC
                logger.critical(f"[ai_writer] Circuit breaker OPEN: {_circuit_state['failures']} failures")
            wait = (2 ** attempt) * 1.0  # 1s, 2s, 4s
            logger.warning(f"[ai_writer] Retry {attempt+1}/{MAX_RETRIES} after {wait}s: {e}")
            time.sleep(wait)
            continue
```

**주의사항:**
- circuit breaker 상태는 모듈 레벨 변수. 프로세스 재시작 시 리셋됨. launchd가 3시간마다 재시작하므로 충분.
- `time.sleep()`은 동기 블로킹. async 전환은 Phase 8 범위 밖.
- 3-tier fallback + tier당 3회 retry = 최대 9회. circuit breaker OPEN 시 5분간 모든 LLM 호출 차단.

**위험:**
- circuit breaker가 잘못된 임계값으로 인해 정상 서비스를 차단할 수 있음. 모니터링 로그 추가 필수.
- metrics에 `ai_writer_circuit_breaker_open` 게이지 추가 권장.
