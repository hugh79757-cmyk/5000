# Phase 49: 크로스링크(cross-link) 생성 버그 근본 수정

## 배경
각 블로그 포스트 하단에 "이런 상품도 좋아하실 거예요" 섹션이 있다.
이 섹션은 다른 블로그(서브도메인)의 관련 포스트로 연결하는 크로스링크를 생성한다.

## 버그 1: 크로스링크 URL의 slug가 실제 포스트 slug와 불일치 → 404
예시 (health 블로그 콜레스테롤 포스트 하단):
- 출력된 링크: `https://baby.informationhot.kr/posts/20260726-젖병-건조대-추천/`
- 실제 존재하는 URL: `https://baby.informationhot.kr/posts/jeojbyeong-geonjodae-recommend-mam-aenliteulbebepeullo-u-yug-a-choboleul-wihan-practical-seontaeg/`

원인 추정: 크로스링크를 생성하는 코드가 포스트의 실제 slug(frontmatter의 slug 필드)를
참조하지 않고, 제목을 기반으로 URL을 임의 생성하고 있음.

## 버그 2: 4개 크로스링크 중 2개만 HTML에 렌더링됨
예시: health 블로그 포스트 하단에 4개 링크가 있어야 하지만,
실제 HTML에는 손목 보호대(fitness)와 도마(kitchen)만 출력되고
젖병 건조대(baby)와 모공 수축 크림(beauty)이 누락됨.

원인 추정: 크로스링크 생성 시 대상 포스트가 아직 생성되지 않았거나,
링크 목록을 markdown/HTML로 변환하는 과정에서 일부가 잘리는 버그.

## 디버깅 지시

1. **크로스링크 생성 코드를 찾아라**
   - 파이프라인에서 "이런 상품도 좋아하실 거예요" 텍스트를 grep하라
   - 해당 HTML 블록을 생성하는 함수/모듈을 특정하라
   - `grep -r "이런 상품도 좋아하실 거예요" --include="*.py"`
   - `grep -r "좋아하실" --include="*.py"`
   - 또는 크로스링크/related/recommend 관련 함수를 찾아라

2. **slug 생성 로직을 추적하라**
   - 크로스링크 URL이 어떻게 만들어지는지 확인
   - 실제 포스트의 frontmatter slug와 크로스링크 URL slug를 비교
   - 불일치의 원인을 정확히 파악

3. **4개 중 2개만 렌더링되는 원인을 찾아라**
   - 크로스링크 목록이 4개로 생성되는데 2개만 출력되는 건지
   - 아니면 애초에 2개만 생성되는 건지 확인

## 수정 요구사항

1. **크로스링크 URL은 반드시 대상 포스트의 실제 slug를 사용해야 한다**
   - 대상 포스트가 이미 생성된 경우: frontmatter의 slug 필드를 읽어서 사용
   - 대상 포스트가 아직 생성되지 않은 경우: 링크를 생성하지 않거나 placeholder 처리

2. **크로스링크 HTML이 잘리지 않도록 보장**
   - 4개 링크가 지정되었으면 4개 모두 HTML에 포함되어야 함

3. **기존 포스트의 잘못된 크로스링크도 수정하는 일괄 스크립트 작성**
   - 모든 content 파일에서 "이런 상품도 좋아하실 거예요" 섹션의 링크를 추출
   - 각 링크의 대상 URL이 실제 존재하는지 HTTP HEAD 요청으로 확인
   - 404인 링크는 같은 블로그에서 가장 유사한 포스트의 실제 URL로 교체
   - 또는 대상 블로그의 /posts/ 목록에서 매칭되는 포스트를 찾아 교체

## 검증
- health 블로그 콜레스테롤 포스트의 4개 크로스링크가 모두 200 응답인지 확인
- 10개 CUAP 블로그 중 최소 5개 블로그의 최신 포스트에서 크로스링크 검증
- hugo --gc --minify 빌드 에러 0건 유지
