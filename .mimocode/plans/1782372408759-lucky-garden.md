# Travel 블로그 발행 최적화 계획

## 목표
- 발행 쿼터 하루 2회로 감소
- 축제는 새로운 것이 있을 때만 발행
- 시郡구 7일 중복 체크 유지

## 변경 사항

### 1. 발행 쿼터 2회로 변경
**파일**: `config/blogs.d/tap.yaml`

- travel-hugo: `daily_quota: 5` → `daily_quota: 2`
- travel1-hugo: `daily_quota: 5` → `daily_quota: 2`
- travel2-hugo: `daily_quota: 5` → `daily_quota: 2`
- travel4-hugo: `daily_quota: 5` → `daily_quota: 2`
- travel3-hugo는 이미 inactive 상태이므로 변경 불필요

**효과**: 하루 총 발행량 약 8-10건으로 감소, 불필요한 시도 60% 감소

### 2. 축제 새로운 것만 발행
**파일**: `pipelines/travel/fetcher.py`

fetch_festival() 함수에서 DEPLETION FALLBACK 시스템 비활성화:
- 라인 311-367: `_is_fallback` 로직 제거
- `published_ids` 필터로 후보 0건이면 바로 None 반환
- fallback으로 이미 발행된 축제를 다시 선택하는 로직 삭제

**효과**: 이미 발행된 축제 재발행 방지, refresh_festival 트리거 후 새 데이터만 발행

### 3. 시郡구 7일 중복 체크 유지
**변경 없음** - 현재 7일이 적절함

## 검증 방법
1. `python3 dispatcher.py travel-hugo` 실행하여 쿼터 2회 확인
2. `python3 dispatcher.py travel1-hugo` 실행하여 축제 fallback 없음 확인
3. 로그에서 "quota reached" 메시지 확인
